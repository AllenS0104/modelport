ABOUT THE PLATFORM

连接模型服务，
而不是让你管理算力。

ModelPort是一层面向用户的模型服务入口：将获准接入的上游 API，整理为可选择的模型、明确的账户权限和可核对的消费记录。我们不自研所有模型，也不提供 GPU 租赁。

普通用户

通过网页聊天使用模型，查看自己的账户和消费。选好模型就可以提问，日常使用在自己的账户中完成。

开发者

通过兼容 API 集成模型，为应用设置独立客户 Key。模型 ID、权限和计费规则均需明确核对。

平台如何工作

你的账户 / 客户 Key → 平台授权与模型路由 → 获准的上游 API → 返回结果与用量结算。

上游凭据由平台保管；客户使用自己的账户或客户 Key。网页与 API 共用 New API 的账户、授权和账本，不额外创建一套计费系统。选择模型是按请求选择服务，不会重启共享服务器。

开始之前，你可能关心

现在可以注册、付费和调用吗？

当前部署仍是本地预览，没有开放购买或承诺可用模型。注册取决于平台实际开通状态；真实调用还需要可用渠道、账户权限和余额。不会用演示回答代替真实服务。

价格怎么算？“折扣”是否等于固定低价？

价格按模型、账户分组和计费项目区分，可能涉及输入、输出、缓存、次数或动态规则。公开分组价格用于参考，不代表每个账户均有该权限；最终以账户适用规则及消费记录为准，不承诺固定折扣或无限量。

普通用户也需要 API Key 吗？

网页聊天使用自己的登录账户，无需粘贴 Key。开发者从客户控制台创建独立 Key；不要把客户 Key 或上游凭据发到聊天、截图或公开代码中。

聊天会保存吗？

当前工作台的对话历史只保存在本标签页内存中，刷新或离开页面后清空。发送时，上下文会交给平台及上游处理；服务端仍保留用量等记录，不代表零留存。正式服务的数据条款与留存政策需在上线前明确。

模型失败或停止生成后，会不会收费？

停止接收不保证上游立即停止，也不保证免单。部分失败存在预扣退还流程，但应先核对消费记录，再决定是否重试；本工作台不会自动重放收费请求。

是否提供 GPU、知识库或文件问答？

不接入 GPU，不提供算力编排。当前提供文本对话与 API 入口；文件问答、知识库、跨设备云端会话和正式 SLA 不是本版已交付能力。

cURL · 先核对请求格式
下载 request.json，把里面的 model 替换为实际获准的模型 ID。在 Linux/macOS 的 Bash 中设置好相同的 Base URL 和客户 Key，再执行：
curl --fail-with-body --silent --show-error --max-time 60 \
  --request POST "${PLATFORM_BASE_URL%/}/chat/completions" \
  --header "Authorization: Bearer ${PLATFORM_API_KEY}" \
  --header "Content-Type: application/json" \
  --data-binary @request.json
不要添加自动重试或跳转参数；不要把真实 Key 直接写进命令。Windows 用户可使用 Python/Node 示例，避免 PowerShell 与 Bash 的引用和换行差异。

3 · 接入自己的前端
浏览器 → 你自己的后端（登录校验、额度与频率限制）→ 平台 API。后端从受保护环境读取 Key，再把结果返回给自己的用户；不要做一个任何人都能转发请求的匿名代理。
先跑通普通响应，再按需要增加流式输出。流式请求使用 stream: true，按 SSE 事件边界解析增量；代理应关闭缓冲。不能假设一个网络数据块就是一条消息，也不能把断流当作成功完成。


常见问题与排查顺序
401核对客户 Key、是否过期或已撤销；不要在日志打印 Key
403 / 模型不可用核对模型 ID、分组权限、Key 限制和账户余额
404检查 Base URL 和端点；避免重复拼接 /v1
429检查额度与限流，遵守 Retry-After，不立即循环重试
5xx / 超时 / 断流先按时间或请求 ID 核对用量，再决定是否重试
HTTP 状态不等于最终账务结果。超时或取消不保证上游未执行；先核对消费记录，不在失败时自动切模型或重放请求。
