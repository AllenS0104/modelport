# 独角鹰网站内容盘点与 API Key 平台调整方案

版本：2026-09-21  
目标网站：<https://dujiaoying.com/>  
适用项目：模港 ModelPort / 独角鹰 API Key 销售平台  
状态：**方案与内容清单；尚未执行旧站删除、域名切换或云部署。**

## 1. 目标与范围

将当前“企业介绍 + 软件分销 + AI 应用生成 + API 聚合”的综合网站，收敛为面向客户的 **模型 API Key 销售平台**。

客户购买模型使用权益后，由平台开通账户额度和允许使用的模型/分组；客户使用自己的平台 Key，接入 WorkBuddy、OpenClaw、支持自定义 API 端点的 VS Code 扩展或其他应用。平台不交付上游供应商原始密钥，不提供网页聊天，不部署本地大模型。

当前付款与开通由管理员审核完成。没有接通自动支付、自动开通或验证免费试用规则前，页面不能宣传相应功能已经可用。

本次盘点来自公开页面，覆盖首页、`#llm-api`、`#aigis`、`#cases`、`#software`及“关于我们”。**没有读取该网站的管理后台、部署目录或数据库，因此本方案不是服务器文件删除清单。**

## 2. 当前内容与处理决定

| 位置 | 现有内容 | 建议 | 理由与实施边界 |
|---|---|---|---|
| 全站导航 | AI文生系统、软件分销、AIGIS入口 | 从新平台导航移除 | 与API Key销售无关；不意味着停止或删除公司的其他业务 |
| 首页首屏 | API聚合与文生应用并列宣传 | 重写 | 明确“购买模型API服务，在自己的客户端使用” |
| 首页产品区 | 文生应用、智能客服、数据分析平台 | 移除或迁至独立业务站 | 不作为本平台已经交付的产品 |
| `#aigis` | CRM/ERP/数据大屏生成、在线Demo、独立套餐 | 从新站移出并归档 | 属于另一套产品和履约体系 |
| AIGIS外链 | 指向外部聊天/应用体验站的入口 | 移除本网站入口 | 只处理本站链接，不删除或停用外部服务 |
| `#software` | 软件、硬件、云采购目录及报价入口 | 迁出或归档 | 保留公司其他业务资料，不与模型API销售混用 |
| `#cases` | 客服、ERP、文生应用等案例 | 删除不相关部分，保留核实后的API案例 | 需确认案例真实性、量化依据及公开授权；可改成明确标注的“应用示例” |
| `#llm-api`模型广场 | 静态供应商/模型名单、“在线测试” | 按实际可售模型重建，取消网页测试入口 | 官网展示不应超过后台真实供应与客户授权范围 |
| `#llm-api`套餐 | 50/500美元月套餐、定制“无限Token” | 替换为真实价格、额度和开通规则 | 现有平台不是已实现这些权益的订阅系统 |
| 费用估算器 | 15%–30%折扣、按调用量估算月费 | 暂移除，或使用真实价格与可解释假设重做 | 费用受模型、输入输出token、缓存、倍率及实际usage影响，调用次数不能直接等同token量 |
| 首页/全站页脚 | 旧产品描述、体验入口、混合业务定位 | 统一改写 | 避免用户误以为可在网站直接聊天或生成应用 |
| 关于我们 | 大篇幅软件代理与AIGIS介绍 | 精简为运营主体与API服务说明 | 只保留与本平台有关且有证据支持的信息 |
| 合作伙伴/证书 | 厂商品牌、代理授权、各类认证 | 核实关联性、有效性与展示许可 | 不把公司某项资质自动等同于本API平台或所有模型的授权 |
| 联系方式 | 主体联系方式及页脚电话 | 保留并统一核对 | 公开页面中的联系电话存在不一致 |
| 法律与备案 | 公司主体、备案、版权、隐私与条款 | 保留、核实、补齐 | 不因内容精简而删除必要的主体与用户权利说明 |

### 需要先核实、不能直接沿用的承诺

- “已接入7家厂商”“20+可用模型”“5个海外节点”等供应与基础设施数字。
- SOC2、GDPR、数据不出境、正式代理授权等资质或合规表述。
- 99.9%/99.99% SLA、24/7支持、响应时延与可用性保证。
- “3000+生成应用”“客户数量”“满意度”“降本比例”等经营数据。
- 免费试用、即时开通、自动付款、无限用量、固定折扣等商业承诺。

这些是**待核验的旧宣传**，不是本方案对其真实性、认证状态或法律效力的判断。没有证据或当前产品支持时，先不上线相关表述。

## 3. 新网站信息架构

建议默认中文，主导航保持简洁：

**首页 → 模型与价格 → 接入指南/API文档 → 常见问题 → 控制台**

| 页面 | 应包含 | 不应包含 |
|---|---|---|
| 首页 | 服务定位、使用流程、支持的接入方式、查看模型与开通入口 | 无依据的客户数、认证、折扣、可用性承诺 |
| 模型与价格 | 实际模型ID、协议能力、计价单位、输入/输出价格、适用分组与限制 | 未接通却显示可购买的模型、未经验证的“无限Token” |
| 接入指南 | 平台Base URL、客户Key配置、模型选择、错误处理与计费说明 | 上游供应商Key、共享客户Key、网页聊天输入框 |
| 常见问题 | 如何开通、如何选择模型、余额与Key额度关系、流式失败和支持渠道 | 与AIGIS生成CRM/ERP无关的平台承诺 |
| 控制台 | 登录后查看模型、管理自己的Key、余额与使用记录 | 将管理员渠道配置或供应商Key暴露给普通客户 |
| 页脚 | 主体、备案、版权、联系渠道、隐私/条款/计费规则 | 未实现的文档入口、无关产品营销链接 |

### 首页建议文案方向

主标题可采用：

> 模型 API 服务，接入你的工作流

副标题可采用：

> 选择可用模型，开通账户额度，使用平台 API Key 接入自己的客户端或应用。

主要按钮：“查看模型与价格”。  
辅助按钮：“查看接入指南”“登录控制台”。  
开通方式尚为人工审核时，使用“联系开通”，不要写“立即自动开通”。

以上是建议稿，不代表已经完成品牌确认或正式营销审核。

## 4. 与平台实际能力保持一致

### 4.1 身份与权益

- 上游供应商Key仅由管理员在渠道中配置；客户获得的是平台签发的客户Key。
- 销售权益以账户余额、服务端可用分组/模型权限为准，不能只依赖客户可自行修改的Key子限额。
- 普通用户常规导航为数据看板、概览、API密钥、使用日志、任务日志；审计入口仅管理员可见。
- 默认简体中文，保留用户明确选择其他语言的能力。
- 普通用户账户安全仅开放密码操作，既有登录验证不降级；不宣传用户可以自助管理当前受限的安全设置。

### 4.2 客户端兼容性

分别提供WorkBuddy、OpenClaw、VS Code兼容扩展和通用HTTP/SDK教程。每份教程都需核实具体客户端及版本是否支持：

1. 自定义Base URL和API Key。
2. 所需协议及模型ID。
3. 流式输出、超时、工具调用和错误响应。

不能把“VS Code支持某个兼容扩展”宣传成“所有VS Code AI产品均可替换后端”；尤其不能默认所有GitHub Copilot功能都能接入第三方API。

### 4.3 计费与故障说明

- 清楚标注计价单位、输入/输出费用、缓存或其他适用倍率，不把调用次数当作token数量。
- 尚不支持的Gemini `countTokens`会明确拒绝，不执行生成或收费。
- Responses转Chat时，不支持的非文本工具输出会明确拒绝；需要此能力时，应使用实际支持的原生Responses渠道。
- 流式输出中途失败时应明确报告错误；已发生的部分上游用量可能仍需结算，不能笼统承诺“所有失败均免费”。
- 邮件通知的界面和隔离测试可用，不代表正式SMTP投递已开通；上线承诺需以实际收件验收为准。

## 5. 品牌、链接和搜索展示

- “独角鹰”与“模港ModelPort”应确定一个对外主品牌及必要的从属关系，再统一导航、标题、Logo、邮件模板和文档；本方案不自动改名。
- 更新页面标题、description、分享卡片和页脚，去掉文生应用/软件分销的旧定位。
- 多个页脚链接未提供实际`href`；本次未穷尽其JavaScript行为，上线前必须逐项验证目标内容，不保留未经确认的空入口。
- 所有法律页面与联系入口在未登录状态下应可达。
- 外部产品链接只从本平台移除，不擅自停用其他域名或服务。

### 旧地址处理

现有导航大量使用URL hash。`#aigis`等片段不会发送到服务器，不能只配置HTTP重定向就认为旧链接已处理。

| 旧入口 | 建议处理 |
|---|---|
| `#llm-api` | 前端映射到新模型与价格页面；以实际平台路由为准 |
| `#aigis`、`#software` | 显示业务迁移说明或返回新首页；如迁至其他站点，仅使用已确认地址 |
| `#cases` | 映射到已核实的API应用说明，或返回首页 |
| 旧网页聊天入口 | 引导到API Key管理或接入指南，不恢复网页聊天 |
| 无效历史路径 | 提供清晰的404和回到首页入口，不静默显示错误产品内容 |

## 6. 分阶段实施

| 阶段 | 工作 | 放行条件 |
|---|---|---|
| 1. 备份与确认 | 保存旧网站源码、静态资源、必要内容和部署配置；确认主品牌、运营主体、联系方式及其他业务归档去向 | 可恢复旧站；明确哪些内容仅迁移、哪些入口下线 |
| 2. 预览改版 | 在隔离预览环境接入新官网/控制台，替换导航、套餐、旧业务和宣传文案 | 不影响现有域名；所有保留链接可用 |
| 3. 产品验收 | 核实模型/价格、登录、Key、权限、余额、使用记录、流式错误和客户端教程 | 使用专门验收账户；不拿生产客户做破坏性测试 |
| 4. 云环境准备 | 统一域名/TLS、反代、持久秘密、数据库磁盘、供应商出站、SMTP、备份和监控 | 满足部署及迁移文档的要求，不直接暴露后端端口 |
| 5. 灰度切换 | 配置旧地址处理、分批切流、观察错误和计费、检查移动端和缓存 | 发布包校验通过，应用回滚路径已演练 |
| 6. 收尾清理 | 观察稳定后再清理不再引用的旧资源，保留合规及业务所需归档 | 不误删仍在使用的资源、其他服务或受保护备份 |

已有客户数据迁移必须使用一致性备份和受保护的秘密传输；不能把GitHub无数据应用包当作数据库备份，也不能在新交易产生后倒灌旧库“回滚”。
